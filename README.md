# P2 — Threat Model Generator

Before a team writes a single line of code, security engineers try to predict where an attacker could strike. This is called **threat modelling** — and it's one of the highest-value activities in a security program. Finding a design flaw in a diagram costs nothing to fix. Finding it after deployment costs millions.

This tool automates threat modelling. Point it at a description of your application, and it produces a full threat inventory with risk scores, compliance flags, and remediation suggestions.

---

## What Problem Does This Solve?

Most teams skip threat modelling because it takes hours of expert time and specialised knowledge. A workshop for one application can take a full day. This tool reduces that to 2 minutes and produces a report that's consistent across every application, every time.

It reads the files developers already write — Kubernetes manifests, Docker configs, API specs — and produces security findings from them automatically.

---

## See It In Action

**Scenario: A startup is launching a mobile banking app.**

Their team writes a `docker-compose.yml` to describe the backend services. Instead of scheduling a threat model workshop, they run:

```bash
python p2_threat_model.py --input docker-compose.yml --output output/
```

**Two minutes later, they have this:**

```
[+] Application: Banking Backend | Components: 5 | Data flows: 7
[+] Overall risk score: 84/100 — HIGH RISK

[+] Critical: 4 findings
[+] High:     9 findings
[+] Compliance flags: GDPR, PCI-DSS

── Top Findings ───────────────────────────────────────────────
  🔴 CRITICAL  Customer database — personal data stored without encryption
  🔴 CRITICAL  Payment API — no rate limiting (can be hammered by attackers)
  🔴 CRITICAL  Cache server — no password, accessible from the internet
  🟠 HIGH      API secret key hardcoded in the config file
```

Each finding includes:
- **What the risk is** — in plain language
- **Why it matters** — the real-world attack scenario
- **How to fix it** — specific, actionable steps
- **Which regulation it violates** — GDPR, PCI-DSS, HIPAA, SOC2 where applicable

The full report is a self-contained HTML file they can share with their team, investors, or compliance auditors.

---

## What Files Can It Read?

| File type | What it is | Who writes it |
|---|---|---|
| **YAML descriptor** | A description of your app's components and data flows | You fill this in |
| **OpenAPI / Swagger** | API documentation | Auto-generated by most API frameworks |
| **docker-compose.yml** | Container service definitions | DevOps / developers |
| **Dockerfile** | Single container build instructions | Developers |
| **Kubernetes manifests** | Cloud deployment configs | DevOps / platform teams |

It auto-detects which type of file you give it.

---

## What Does the Report Include?

- **Risk score** (0-100) with severity breakdown
- **Full threat list** — every potential attack, scored by likelihood and impact
- **MITRE ATT&CK mapping** — connects findings to the real-world attack techniques hackers use
- **Compliance flags** — tells you which regulations you may be violating and why
- **Remediation priority** — what to fix first, with effort estimates
- **AI-generated explanations** — the top findings get a plain-English explanation of the business risk (runs locally, your data never leaves your network)

## How to Run It

```bash
git clone https://github.com/PyHackSecGP/p2-threat-model-generator
cd p2-threat-model-generator
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# Run on the included sample app
python p2_threat_model.py --input examples/webapp.yaml --output output/

# Run on a Kubernetes deployment file
python p2_threat_model.py --input examples/k8s-webapp.yaml --output output/

# Use the interactive guide instead of a file
python p2_threat_model.py --wizard
```

Open the `.html` file in `output/` in any browser.

**No AI required to get started.** The `--no-llm` flag skips the AI explanations and produces the full threat inventory using rules alone — useful in CI pipelines or when you just want the scores fast.

---

## CI/CD Integration

A GitHub Actions workflow is included. On every pull request that touches application configuration files, it:
- Runs the threat model automatically
- Posts the risk score and top findings as a PR comment
- Uploads the full HTML report as a downloadable artifact

Teams can set a risk score threshold and block PRs that exceed it — the same way you'd block a PR with failing tests.
